`Jase-SecKit` は、バグバウンティ、認可された Web セキュリティテスト、AI 支援の脆弱性研究のための個人リポジトリです。

本リポジトリは、バグバウンティ Skills とセキュリティ研究資料を再整理・精簡化・翻訳・エンジニアリング改造したものです。重複または低価値なコンテンツを削除し、Word レポート自動生成の冗長モジュールを除去し、Skill 内容を英語に統一するとともに、グローバル行動制約、状態ファイル機構、Prompt、Burp MCP と Chrome DevTools MCP の利用設定を追加しています。

---

## 基本原則

> 広く探索し、厳密に検証する。完全な証拠なしに脆弱性を確認しない。

本リポジトリは以下の原則を重視します：

- サーバーサイドの認証、認可、オブジェクト所有権、テナント分離、状態遷移、ビジネスルールを主要なセキュリティ境界とする。
- 静的解析、スキャナー結果、エラーメッセージ、コードパターン、過去の事例は手がかりを生成するだけであり、動的検証の代替にはならない。
- 技術的ヒットは脆弱性の成立を意味しない。得られた能力、影響対象、データや資産、ビジネス結果、影響範囲、前提条件を引き続き検証する必要がある。
- 状態と証拠をファイルに保存し、モデルがコンテキスト内の記憶のみに頼ってテストを繰り返したり、漏らしたり、結論を捏造したりしないようにする。
- Skills は導引のためのものであり、未知の経路に対するモデルの自律的な発散や非定型な検証を制限すべきではない。
- すべてのテストは合法かつ明示的に認可され、制御可能な環境に限定する。

## リポジトリの役割

### 1. グローバル Agent 制約の提供

`约束文件/AGENTS.md`（中国語版）と `约束文件/CLAUDE.md`（英語版）がグローバルなセキュリティテスト制約を提供します。

制約ファイルの主な用途：

- 認可された対象、資産、インターフェース、アカウント、テスト範囲を限定する。
- 未認可のスキャン、破壊的検証、永続化、横展開、リソース枯渇などの行動を制約する。
- 手がかり、技術的ヒット、危害検証、最終的な脆弱性結論を明確に区別する。
- モデルがツールの警告、HTTP 200、異常なレスポンス、理論上の攻撃チェーンを確認済み脆弱性として記述することを防ぐ。
- モデルに `state/blackboard.md` の読み取りと更新を義務付け、記憶に頼って黒板を捏造・再構築するのではなく、ファイルをタスク状態の情報源とする。
- 検証済み、未再現、低収益、入力不足のブランチに明確な終端状態を用い、復旧・再確認・継続テストを容易にする。

### 2. MCP とクライアント設定の提供

`设置/` ディレクトリには Claude Code、Codex、ZCode などのクライアント向け設定例が含まれており、主に以下を統合します：

- Burp MCP：プロキシ履歴の読み取り、リクエストの構築とリプレイ、リクエスト/レスポンスの検査、動的検証の支援。
- Chrome DevTools MCP：ブラウザセッションの再利用、ページ操作、ネットワークリクエスト解析、コンソール検査、パフォーマンス分析、メモリデバッグ、実験的 DevTools 機能。

これらの設定は汎用のプラグアンドプレイファイルではありません。使用前に本機のパス、MCP サービスアドレス、クライアントバージョン、対応パラメータを確認し、例中のプレースホルダーパスを実際の絶対パスに置き換えてください。

### 3. バグバウンティ Prompt の提供

ルートの `Prompt.md` は 2 つの部分から構成されます：

- 前半：ローカルのオープンソースプロジェクト、演習環境、認可対象に向けた深い脆弱性発掘と動的再現のプロンプト。DeepSeek、Kimi、GLM などの自律実行寄りのモデルとの併用に適する。
- 後半：Codex / GPT-5.6 向けの、Web サイトアーキテクチャ、JavaScript、インターフェース、状態遷移、実際の動作メカニズムの分析プロンプト。

Prompt は段階的な導引として使うのが適しています。グローバル制約ファイルと組み合わせ、モデルの自律的推論能力を保ちながら、結論にコード位置、インターフェースパス、パラメータ、レスポンスフィールド、呼び出し関係、ネットワーク記録などの検証可能な証拠を付けるよう要求できます。

### 4. 方法論参考資料の保持

リポジトリには AI 脆弱性発掘 Agent の設計に関する 3 つの参考資料が保持されています：

- `AI辅助漏洞挖掘系统设计指南.pdf`
- `围绕Loop的AI SRC系统设计.pptx`
- `客户端漏洞挖掘 Agent 的设计与实践.md`

これらの資料は、統一的な脆弱性発掘 Skill の精錬に利用できます。例えば、Loop、状態管理、動的検証、証拠監査、盲点レビュー、Agent オーケストレーションの手法を、より軽量なエントリー Skill に統合できます。

これらのファイルは参考・参照資料です。原作者の権利、元のライセンス、出典表示は本リポジトリの MIT License によって変更されません。

## グローバル制約と黒板メカニズム

- グローバル制約は、何が許可されるか、いつ脆弱性を確認できるか、状態をどう保存するか、いつブランチを終了するかを定義する。
- Prompt は現在の対象に応じてモデルの関心と推論方向を変える。
- MCP は実際のブラウザと HTTP 対話能力を提供する。

推奨される基本ループ：

```text
黒板を読む
  → 露出面とオブジェクト関係を構築
  → 検証 Intent を生成し優先順位付け
  → セキュリティ境界を動的に検証
  → 技術的ヒットをマーク
  → 実際の危害を検証
  → Guardian レビュー
  → 深刻度評価または明確な終端状態へ
  → 黒板を更新
```

黒板はタスク復旧、重複排除、証拠の完結に必要な情報のみを保存し、完全な思考過程は保存せず、モデルが既存の状態ファイルから逸脱して独自に捏造することもあってはなりません。

## MCP とブラウザ設定

### Burp MCP

Claude Code の設定例は以下にあります：

```text
设置/claude-code/managed-mcp.json
```

使用前に以下を変更：

```json
"command": "<絶対パス>\\java.exe"
```

および：

```json
"<絶対パス>\\mcp-proxy.jar"
```

デフォルトの例では以下のアドレスで Burp MCP サービスに接続します：

```text
http://127.0.0.1:9876
```

Burp 側の拡張機能、プロキシプログラム、ローカルポートが正しく起動していることを確認してください。

### Chrome DevTools MCP

現在の設定は、Chrome DevTools MCP のブラウザ、ネットワーク、実験的 DevTools、ビジュアル、構造化コンテンツ、全ページ、メモリデバッグ、サードパーティツール、WebMCP などの機能を重点的に有効化しています。

主要パラメータ：

```json
"--autoConnect"
```

このパラメータは、本機で実行中の互換性のある Chrome インスタンスへの自動接続を試みます。Chrome のリモートデバッグポリシーとローカル環境が許す場合、既存のブラウザ設定、ログイン状態、Cookie を再利用でき、既存の認可セッション内で直接ページを分析するのに適しています。

分離されたセッションが必要な場合は `--autoConnect` を削除し、起動・接続する Chrome に独立したユーザーデータディレクトリまたは専用ブラウザプロファイルを設定してください。パラメータを削除するだけでは、すべてのクライアントが自動的に分離環境を作成するとは限りません。実際の動作は MCP クライアントと Chrome の起動方法に依存します。

設定では以下も使用します：

```json
"--channel=stable"
```

これは Chrome Stable チャンネルを選択するものであり、スキャンパラメータではありません。

一部の `--experimental-*` パラメータは Chrome DevTools MCP のバージョンによって変わる場合があります。アップグレード後は現行バージョンの公式パラメータ説明を基準とし、起動失敗時は実験パラメータを一つずつ外して原因を切り分けてください。

## 使い方

### 1. グローバル制約の設定

クライアントに応じて選択：

- Codex または `AGENTS.md` をサポートする環境：`约束文件/AGENTS.md` を使用。
- Claude Code：`约束文件/CLAUDE.md` を使用、または必要に応じて既存のプロジェクト制約ファイルにマージ。

既存のグローバルルールを直接上書きすることは推奨しません。競合項目を確認してからマージし、認可範囲、状態ファイルパス、ツール権限が実際の環境に合致することを確認してください。

### 2. MCP の設定

`设置/` から対応クライアントの設定を参考として選択し、本機のパスとサービスアドレスを置き換えてから、以下を検証：

- MCP サービスが正常に起動するか。
- Burp がテストリクエストを読み取り・作成できるか。
- Chrome が期待されるブラウザインスタンスに接続するか。
- 現在のブラウザセッションが再利用セッションか分離セッションか。
- 実験的パラメータが現行バージョンでサポートされているか。

### 3. Prompt の使用

`Prompt.md` をそのまますべての対象に使わないでください。タスクごとに対象、範囲、環境、アカウント、禁止事項、期待する出力を置き換え、グローバル制約と併用することを推奨します。

モデルに「Critical 脆弱性を必ずいくつか見つけなければならない」と要求すると、確証バイアスが生じる可能性があります。実際の運用では：脆弱性の数や等級は事前に設定せず、動的検証を経て危害のループが完結した問題のみを最終報告してください。

## 推奨される作業方法

1. 対象、アカウント、許可された資産、除外項目を明確にする。
2. グローバル制約と既存の黒板を読む。
3. ディレクトリ、フレームワーク、依存関係、設定、JS、インターフェース、オブジェクト関係を分析する。
4. 主体、エントリーポイント、オブジェクト、関係、アクション、状態、信頼フィールドのモデルを構築する。
5. 全工程を一度に固定するのではなく、Prompt で現在の段階を導引する。
6. Chrome MCP で実際のページと呼び出しチェーンを再現し、Burp MCP でサーバーサイドの境界を検証する。
7. ツールのヒットは手がかりまたは技術的ヒットとしてマークし、すぐに脆弱性として書かない。
8. 異なる身分、オブジェクト、テナント、エントリーポイント、状態、リクエスト形態で対照する。
9. 確認した問題について、リクエスト、レスポンス、状態変化、ログ、ファイルなど再現可能な証拠を保存する。
10. 独立したレビュー、盲点チェック、重複排除、危害評価を完了する。

## Skills についての個人的な見解

大規模モデルの能力が急速に発展する段階で、現実的な問題があります：Skills はまだ重要なのか？モデル自体はすでに十分に強いのではないか？Skills は逆にモデルを制限しないか？

大規模モデルは現在、強いコード理解、ツール呼び出し、攻撃面分析、自律推論の能力を備えています。Skills がまったく無意味とは言えませんが、過度に細分化・手順化・チェックリスト化された Skills は、確かにモデルの発散能力を制限し、モデルを決まったパイプラインに沿って機械的に動かす可能性があります。

バグバウンティは既知の経路ではありません。起点と目標は明確でも、中間の経路は多くの場合未知です。本当に価値のある脆弱性は、異常な状態、ビジネスの組み合わせ、モジュール間の関係、歴史的な互換ロジック、パースの差異、開発者が予期しない相互作用から生まれることがよくあります。これらの経路は、モデルが自律的な推論、連想、探索を保つことを必要とし、固定された Skill によって事前設定されたチェックリストに閉じ込められるべきではありません。

しかし Skills には依然として価値があります。モデルにどう始めるか、どのセキュリティ境界に注目すべきか、状態をどう記録するか、危害をどう検証するか、証拠が十分かどう判断するか、漏れをどう防ぐかを伝えることができます。能力が弱く、早期に収束しがちで、セキュリティテストの経験が不足しているモデルにとって、適切に設計された Skills は脆弱性発掘の品質を大きく向上させられます。

現在より重視しているのは Prompt のプロセスです：現在の段階、既知の証拠、自身の判断に基づいてプロンプトを継続的に調整し、モデルが固定の流れを常に実行するのではなく、実際の発見に沿って深掘りできるようにします。Skill は基礎フレームワーク、知識インデックス、漏れ防止の役割を担い、Prompt が段階的な導引を担い、モデル自身が未知の経路での発散的思考を担います。

将来、Skills の重要性はさらに低下する可能性があり、効果を決める核心は、モデル自身の推論能力、ツール能力、コンテキスト管理、動的検証能力にますます依存するでしょう。プロセス制約を増やし続けるよりも、モデルに明確で安定し、過度に拡張しない行動境界を確立し、すべての結論を真実の証拠に戻すよう要求する方が重要です。

## 利用範囲

本リポジトリは以下の場面にのみ使用できます：

- 明示的に認可されたバグバウンティおよび SRC テスト範囲。
- ユーザー自身のシステム、テスト環境、ラボ、ローカルに構築したオープンソースプロジェクト。
- CTF、演習環境、セキュリティ講座、防御的研究。
- 認可されたコード監査、インターフェーステスト、ブラウザ分析、脆弱性再現。

以下への使用を禁止します：

- 認可のないサードパーティシステムへのスキャン、探査、侵入、悪用。
- DoS、DDoS、持続的な負荷テスト、リソース枯渇、業務可用性に影響する行為。
- 実際の業務データの削除、破壊、不可逆的な改変。
- WebShell、バックドア、スケジュールタスク、スタートアップ項目、リバースシェル、その他の永続的アクセスの確立。
- 横展開、無関係な資産への攻撃、認証情報の窃取、フィッシング、クレデンシャルスタッフィング、ソーシャルエンジニアリング。
- テスト以外のアカウントに対する実際の支払い、返金、権限変更、一括通知、その他の高影響の業務操作。
- 適用法律、プラットフォームルール、バグバウンティポリシー、SRC ルール、対象側の明示的な制限に違反する行為。
