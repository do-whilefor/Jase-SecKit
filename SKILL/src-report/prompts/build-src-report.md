# src-report 维护提示词

检查并优化本仓库的 `src-report` 技能。以 `SKILL.md`、`references/` 和脚本为当前实现；平台采集来源和核对范围见对应 JSON 与指南，`SRC提交字段汇总.md` 保留京东、美团、快手的早期采集记录。计划书和流程图片不作为运行或维护的前置依赖。

用户只需提供证据材料和 SRC 平台。助手负责整理杂乱材料、建立证据关联、按目标平台的独立字段撰写，最终主要交付 `report.md`。中间 JSON 保存在任务目录供补证和复核，无需用户手工填写。

先按 `references/assessment.md` 筛选证据，再评估有依据的 CVSS 3.1 Base。过滤是线索升级门槛，不是按漏洞关键词拒绝；缺少边界失效、稳定复现或实际影响依据时输出线索记录。评分按 FIRST 公式计算，逐项保留依据，不机械映射 SRC 等级。`refer/` 仅为用户输入参考，技能运行不依赖该目录。

保持入口简短，平台细则只放对应配置与指南。不要增加无实际用途的层次、服务或依赖。整理过程保留来源、身份及对象关系、未验证和冲突信息；不能执行 PoC、扩大影响或为填满字段编造证据。

PoC 先判断取舍再写入报告，交付前检查整篇内容的必要性、重复和证据完整性，并记录 `content_review`。精简规则以数据契约为准；不按字段名自动删请求，不把阅读摘录当成已验证的最小 PoC，不以精简替代平台要求的完整材料。程序校验只核对复核声明，不能认证语义。

修改后运行 `python -m unittest discover -s tests`，对变化补充行为测试；平台规则变更需要来源依据。使用临时目录中的合成材料验证登记到 Markdown 的流程，必要时进行独立技能试用。计划书、真实材料、凭据、产物和缓存不进入提交，每次完成修改后创建对应 Git commit。
