# 腾讯 SRC 内容指南

只在目标为腾讯时读取本指南和同目录 `tencent.json`。配置版本为 `2026-10-07.1`，**2026-10-07** 通过 Chrome MCP 读取 [官方漏洞提交页面](https://security.tencent.com/index.php/report/add) 的可见表单、DOM 属性及正文模板。未填写真实报告、保存、上传或提交，页面规则不等于服务端校验已实测。

## 字段与正文

默认表单保留八个独立控件：`title`、`type_primary`、`type_secondary`、`url`、`severity`、`details`、`attachments`、`agreement`。前六项所属表单标签具有 `t-form__label--required` 必填样式，漏洞类型为共用标签的一级和子类型两个选择框。附件和协议没有必填标记，配置的 `required=null` 表示尚未确认，不能认定可以留空。

已依次切换九个一级类型，记录 62 个对应子类型，排除两个“请选择”占位项，保留“其他/其它”等页面原词。子类型通过 `parent_field` 与 `options_by_parent` 绑定一级，不能跨类拼接。未逐一选择所有子类型，不能排除额外联动。危害自评有无危害、低危、中危、高危、严重五项；“无危害”是采集时默认值，不表示用户自评，也不能直接按 CVSS 严重性替换。

选择 **Web漏洞** 时增加两个必填多行字段 `request_packet`（漏洞请求数据包）和 `response_packet`（漏洞响应数据包）。提供对应的完整脱敏结构并定位原件；没有响应时明确列缺口。正文解释关键变化和结果，避免重复整包；阅读摘录须注明省略范围与原件定位，不能冒充完整数据包，脱敏内容不保证可直接重放。

选择 **PC客户端漏洞** 或 **移动客户端漏洞** 时增加三个必填单行字段 `app_name`、`app_version`、`app_description`。APP 描述占位为“请输入APP下载地址等信息”，不是漏洞详情正文。`when.in` 将同一组字段用于两个客户端分支；材料中未知的版本或下载地址不能靠猜测补齐。其余已观察的一级分支未出现这五个条件字段。

`details` 是一个编辑器，按页面四段模板写作：

1. **漏洞描述**：完整请求地址、关键参数、是否需要测试账号、工具名称。账号、密码在模板中出现，不是独立输入框；实际凭证保留在受控原件，由用户在提交时人工补填。
2. **复现步骤**：按权限内正常请求 → 构造 Payload → 测试请求 → 响应结果组织，关联顺序截图或视频。缺少执行结果或正常对照时明确指出，不能用脚本内容代替成功证据。
3. **危害说明**：提供具体可证实的影响与范围。页面的泄露、盗号、篡改是示例，不应直接套入报告。
4. **修复建议**：针对根因给出建议，放在正文中，不增加独立表单字段。

页面提交前提示要求步骤清晰可复现、请求/响应截图、具体危害说明及不放外部链接，并建议附件转 PDF。报告中的引用应指向随案提交的材料和内部证据编号；源 URL 和规范链接属于本配置的采集溯源，不能据此认定可在报告正文放任意外链。

## 附件和人工事项

主表单附件 `accept=.pdf,.zip`，页面分别标注 PDF **小于 10M**、ZIP **小于 100M**。配置按扩展名保存不同阈值，使用严格小于和保守十进制换算；真实 M 单位与服务端边界尚未验证。总附件数量、编辑器图片/视频限制与正文长度上限均未确认。

侧边“漏洞预检”另有支持 `image/*,.pdf,.docx` 的上传入口，不属于主表单报告附件，不并入附件支持范围。没有上传、预检或读取用户历史报告。

一个协议复选框同时对应《TSRC用户服务协议》和《TSRC安全测试规范》，由用户阅读后人工处理；不自动勾选。相关全文、重复漏洞认定与奖励规则未核验，不据其入口或宣传文案推导漏洞评级、奖励金额或收录保证。
