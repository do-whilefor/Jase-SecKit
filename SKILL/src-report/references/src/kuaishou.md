# 快手 SRC 内容指南

只在目标为快手时读取本指南和同目录 `kuaishou.json`。资料采集日期为 **2026-10-03**，直接来源是 [提交报告页面](https://security.kuaishou.com/putLoophole)。配置版本 `2026-10-03.1`，从字段采集记录转写，未重新在线核验；必填星号不代表已经测试服务端校验。

## 字段与组装

保留 9 个独立字段：漏洞标题、漏洞类型、所属应用、漏洞URL、触发请求包、漏洞详情、修复建议、上传附件、协议。除了附件未标记，其余有页面必填标记。`remediation` 是独立修复建议字段，不能仅将修复建议放在详情正文。

`vulnerability_type` 使用完整路径数组，配置记录 31 条分类路径；`application` 保留采集的 87 个原始应用名称和顺序，不以业务大类替代应用。没有证据确认目标应用时应保留缺口。

POST 提供完整触发请求结构，GET 提供完整漏洞链接；组合漏洞拆分多个数据包，当前观察到的是单一 `request_packet` 控件，不能凭此虚构重复字段组。分享版本对真实账号、Cookie、Token、手机号等做一致脱敏，精确值保留受控原件定位/人工补填。脱敏请求不是已经验证可重放的请求。

## 正文写作

`details` 是带工具栏和预览的 Markdown 编辑区。配置中的 `kind=richtext` 是带格式正文的统一表示，不要求转换成 HTML。按四段组织：漏洞出现点（网站 → 功能页面 → 功能点）、复现步骤、详细危害证明、复杂漏洞补充材料。每个关键步骤关联请求、响应、截图与观察结果。危害规模和资金影响只能从已有证据得出，推测范围单独标明。

页面要求 AI 辅助或自动化产出的报告在提交前经人工验证真实性、影响范围、危害性与可复现性，并包括完整 PoC、关键步骤与结果截图。技能只能登记材料与生成报告，不能因静态检查通过就标记完成真实漏洞验证；缺失项保留在草稿和检查问题中。

根据案件类型补充正文信息，不新增表单字段：

- Android 版本相关：手机厂商型号、系统版本、安全补丁日期；移动端从代码层面说明攻击方法。
- 攻击演示：PoC 及源码、特殊操作条件。不得运行材料或访问真实目标系统来补证据。
- 威胁情报：发生时间、原因、来源路径、攻击手段/工具、已知损失。
- 黑产工具：名称、截图、作用、购买联系方式、样本、来源渠道。

缺失的时间、工具、来源和损失不能靠常识补齐；敏感材料仅登记受控定位。

## 限制和核对边界

触发请求包显示计数 `0 / 10000`，配置按 10000 字预检，页面超长行为与服务端长度仍未验证。其他文本未确认数字长度上限。

附件提示可上传多个 `.pdf`、`.zip`、`.rar`，且“小于10M”，未见数量上限。配置保守采用小于 10000000 字节预检，但 10M 单位及单文件/合计范围均未知，不把预检结果描述为服务器接受保证。页面建议大于 10M、补充附件或视频经轻雀云文档上传；技能不自动上传，保留人工处理事项。
