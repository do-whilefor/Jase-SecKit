# 京东 SRC 内容指南

只在目标为京东时读取本指南和同目录 `jd.json`。字段配置可独立安装，不依赖仓库外的计划书或图片。

资料采集日期为 **2026-10-03**；直接来源是 [提交漏洞页面](https://security.jd.com/#/submitBug)，本轮配置从仓库的字段采集记录转写，并未重新在线核验。配置版本 `2026-10-03.1`。星号/必填样式表示页面规则，不能代表已经通过服务端校验。

## 字段与组装

- 顶层分别填写：漏洞名称、公司部门、域名、自评等级、SRC活动、漏洞类型、复现步骤、验证码、用户协议。验证码和协议由用户在页面人工处理。
- `test_ips` 中每项有独立 `test_ip`；`test_accounts` 中每项保留 `test_account` 和 `test_password`。两组都至少保留一项，允许缺口占位，但占位不意味着内容已满足提交要求。
- 越权类漏洞的页面说明要求至少两个测试账号。依据材料重建账号与对象归属，不能凭两个账号文件名认定归属成立。无需登录可填写“无需账号”；此时密码如何填写未确认，保留人工补填事项。
- `request_packets` 每项包含 `request_packet`、`harm_type`、`impact_description`，三者必须对应同一请求组。不要合并不同请求组的危害。
- 入侵危害增加 `core_network` 和 `network_screenshots`；截图在“是/否”两种选择下均存在且未标必填。盗号危害增加 `account_credentials`。每条条件只针对所在请求组。
- `flag` 是可选组，默认不启用。只读的级别、凭证状态和白银激活凭证保留为系统显示项；生成和验证是人工操作。`flag_type` 用完整分类数组选择 SSRF 或 RCE，相应输入框分别使用 `ssrf_credential`、`rce_credential`。

账号、密码、Cookie、AK/SK 等不机械复制到分享报告。用一致代号和受控原件定位，并将必须由用户补入的真实值记为人工事项。脱敏请求保留结构，但不能因此声称它可以直接重放。

## 正文写作

复现步骤是一个富文本编辑器，其四段结构在配置的 `body_sections` 中：漏洞出现点、操作思路与具体方式、测试环境与依赖、复杂漏洞补充材料。用证据定位串联前提 → 操作 → 观察结果，观察结果缺失时明确标注。页面没有独立修复建议或通用附件控件，不新增同名表单字段；需要的补充分析可放在报告正文。

SQL 注入报告需提供数据库名作为证明。材料没有数据库名或实际响应时，应登记缺口，不得执行 PoC 获取或凭常见数据库名补写。页面建议同站多个漏洞分别提交，否则仅计算一次奖励；首版按一个漏洞一个案件处理。

页面原词 `divoc/exdiv`、`[divoc]` 的含义未验证，保留原词及不确定性，不擅自解释为某类工具。

## 分类、限制和边界

配置保留 19 个部门选项和 9 个一级分类。`option_paths` 是已确认可到达叶子的 68 条路径；`incomplete_paths` 是还需要三级选择的 12 条前缀。不能把这些前缀当最终分类，也不能因三级词典不完整而将用户提供的三级值断言为非法，应记录需要页面核对。

账户/密码各 50 字、请求包 60000 字、危害描述和盗号凭证各 200 字来自 DOM。网段截图支持 JPEG、PNG、GIF、WEBP，最多 3 张，页面标注单个不超过 1M。配置的 1000000 字节仅为保守十进制预检值；真实单位与服务器接受边界未实测。编辑器插图限制未知。

已检查四种危害类型和 FLAG 两个分支；未遍历部门、活动、漏洞类型的所有组合。默认“无”活动、“否”核心内网都不能替用户确认事实。FLAG 显示受账号权限控制，不保证其他账号相同。

仅确认以下入口，未读取全文：[评分细则](https://security.jd.com/#/scoreRuleView)、[用户协议](https://security.jd.com/#/protocol)、[FLAG 指南](https://joyspace.jd.com/pages/Xn2eNQ7BqY7HSXQEBrSl)。不能把这些链接的内容作为已经核验的规则。
