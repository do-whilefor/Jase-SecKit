# 百度 SRC 内容指南

只在目标为百度时读取本指南和同目录 `baidu.json`。配置版本 `2026-10-07.1`，来源是 **2026-10-07** 通过 Chrome MCP 读取的[官方漏洞提交页](https://bsrc.baidu.com/v2/#/loophole/create?language=zh)。来源不保留会话参数，未填写、上传、保存或提交报告。

## 字段与正文

主表单有 9 个独立字段：漏洞名称、漏洞类型、漏洞最终造成的危害、危害自评、漏洞链接、漏洞详情、上传附件、验证码及协议。除附件和协议未标星号外，其余均标必填。验证码与协议留待用户现场处理，不读取验证码或自动同意协议。

漏洞类型是在同一个下拉面板中按 9 组展示的 41 项，选中后页面显示“组名 > 类型名”。配置用 `cascade` 的完整路径数组表达这个归属，例如 `["基础架构", "基础设施弱口令"]`，并不表示页面要逐层展开菜单。不能只写有歧义的“其他”或将不同组的同名类型混为一项。

`harm_type` 是独立的最终危害选择，共 11 项；`severity` 是五个等级按钮表达的单选值。漏洞类型、最终危害和危害自评分别依据材料填写，不能从“SSRF”“SQL注入”等名称直接推断已经访问内网或取得数据。页面默认显示“其他危害等”不构成用户结论；CVSS 不替代平台自评。

`details` 是一个富文本编辑器，按原模板写发现方式、漏洞证明、修复方案。发现方式包括场景、前提、操作和截图定位；漏洞证明整理已有 PoC 与实际结果，标明未验证范围；修复方案给出对应建议。模板中的 PoC 不授权执行，修复方案不是独立输入框。页面“参与活动”当前仅有“当前暂无活动”文本，没有选择控件，不新增活动字段。

## 限制与核对范围

标题、漏洞链接、验证码的 DOM `maxlength` 分别是 50、500、4。详情计数器显示总计 10000 字符，配置用 `length_basis=editor_counter` 将其作为文本预检值；超出时仅提示 warning，要求到页面核对计数，不断言无法提交。这不是 textarea 的 DOM 属性，富文本、HTML 与脚本 UTF-16 计数是否一致及服务器边界未经验证。确实超长的内容应人工调整，不能静默截断证据。

报告附件分两档：DOCX/DOC 标注大小限制 8M，APK/IPA/AAR/ZIP/JAR/RAR/7Z 标注 500M。配置逐扩展名保存保守十进制阈值，大小作用范围、等于阈值是否接受和数量上限均未确认。页面没有将 PDF 列入报告附件格式，不能沿用其他平台的限制。顶部 AI“上传并解析”的 DOCX 单文件不超过 10MB 属于助手入口，不是报告附件规则，也不自动使用该入口。

已逐个选择 11 个危害选项，当前观察到的字段和必填标记均没有变化。未逐选全部漏洞类型或遍历类型与危害组合，核对范围仍为 partial，不保证所有条件联动已经覆盖。服务协议全文和服务端校验未核验；必填标记、菜单枚举及大小提示均只代表采集时页面规则。
