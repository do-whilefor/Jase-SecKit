# 美团 SRC 内容指南

只在目标为美团时读取本指南和同目录 `meituan.json`。资料采集日期为 **2026-10-03**，直接来源是 [提交漏洞页面](https://security.meituan.com/#/submitLeak)。配置版本 `2026-10-03.1`，从字段采集记录转写，未重新在线核验；页面必填标记不代表服务端校验已经验证。

## 字段与组装

12 个独立控件保留独立键：`title`、`type_primary`、`type_secondary`、`url`、`test_ip`、`test_account`、`severity`、`details`、`attachments`、`captcha`、`contact`、`agreement`。不把正文的四段模板另建为表单字段。

漏洞类型分成一级与二级。`type_secondary.options_by_parent` 仅允许对应一级的已观察选项，保留页面原词，包括“其 他”、反斜线和大小写。切换一级后自动选第一项不是合理分类的证据，必须按材料判断。

测试 IP、测试账号、级别、附件、联系方式、协议均未标必填，配置以 `required=null` 表示“未确认”，不能推导为服务端允许省略。低危和协议勾选是采集时默认，不是用户确认。验证码和协议由用户在页面人工处理。

测试身份、账号、订单、手机号、Cookie 等分享内容应使用一致代号、脱敏值或受控原件定位。真实值需要精确补填时登记人工事项，不能宣称脱敏请求可直接重放。

## 正文写作

`details` 是一个富文本编辑器，按四段组织：

1. **漏洞描述 & 发现方式、漏洞利用及危害**：交代发现方式、利用条件、实际观察危害和业务范围；多版本产品补充测试 App 版本。
2. **漏洞的详细复现 / 证明过程**：解释关键接口参数，按步骤关联请求、响应、截图、脚本 PoC 和技术信息。PoC 设计意图与观察结果分开。
3. **测试源信息**：提供一致测试身份、订单代号、测试 IP 以及必要的受控原件定位，用于溯源。
4. **修复方案**：针对已确认根因提出具体修复。美团没有本轮确认的独立修复字段，修复方案保留在 `details` 内。

原文“脚本poc、保护解析代码（放在代码框中）”里的“保护解析代码”没有进一步说明，不能自行赋予特定技术含义。

## 分类、限制和边界

配置保留 7 个一级分类、合计 103 个二级选项。已依次切换全部一级分类，未见可见字段变化；未逐一选择所有二级分类，不能排除未观察的联动。DOM 中隐藏的“漏洞描述”“漏洞证明”不列为当前额外字段。

附件仅记录页面的 `.doc`、`.docx`、`.zip` 和“10MB以内”。控件单次选择一个文件不等于总附件上限为 1，配置不写 `max_items=1`。10000000 字节是保守十进制预检值，真实字节单位与单个/总量作用范围未实测。编辑器插图 `accept=image/*` 且可多选，但图片大小与数量上限未知。未显示文本长度限制不等于后台无限长。
