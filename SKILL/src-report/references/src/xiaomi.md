# 小米 SRC 内容指南

只在目标为小米时读取本指南及 `xiaomi.json`。配置版本 `2026-10-07.1`，**2026-10-07** 通过 Chrome MCP 核对 [安全漏洞提交页](https://sec.xiaomi.com/#/security) 的可见表单、控件属性、模板及重要提醒。独立隐私入口未核对，本配置只覆盖安全漏洞页；未填写、上传、保存或提交报告。

## 字段与证据

基础项为 `title`、`type_primary`、`type_secondary`、`severity`、`details`、`captcha`、`attachments`、`agreement`。两个类型选择框共用必填标签；标题、等级、详情、验证码、协议也有 `ant-form-item-required` 样式。附件未标必填，`required=null` 表示未知，不保证可以省略。

已滚动读取并切换 11 个一级选项，其中 8 类有已核对的二级列表；“服务指纹”“test_sunnan3_create”“垂直越权测试类型”显示暂无数据，缺少父映射表示待核对，不能以空枚举认定所有二级值非法。两个带测试字样的分类只代表页面观察，不证明是正式收录类别。已记录的二级选项保留页面原词，包括竖线、空格和大小写。等级为严重、高危、中危、低危四项。

| 一级选择 | 独立字段 |
| --- | --- |
| 移动应用漏洞 / 移动终端安全漏洞 | `business_name` 业务名称未标必填；`package_name` 目标包名必填、DOM 最长 200；`app_version` 版本未标必填；`component_name` 目标组件名称必填、DOM 最长 300。 |
| 其余九个已观察一级 | `url` 完整url必填；`test_account` 测试账号、`test_password` 测试密码未标必填。 |

共 15 个字段定义，按一级条件启用，不能要求移动分支补不存在的 URL/账号密码框。移动控件复用 `basic_fullUrl`、`basic_testUsername`、`basic_testPassword` DOM id，分别显示目标包名、版本、目标组件名称，应按可见标签映射，不能把组件名误当密码。

版本输入提示“不填默认为最新版本”，不能据此声称材料已验证最新版本；没有实际版本证据时列缺口并提醒页面默认差异。业务下拉展开显示“暂无数据”，选择移动应用的“移动客户端组件漏洞”后仍如此，不编造选项或设置空的封闭枚举。未逐一选择所有二级检查额外联动。其他未见 DOM maxlength 的字段也不能认为后台无限制。

测试密码是独立普通文本输入框，配置强制人工补填；分享报告不输出真实密码。页面提示逻辑等身份鉴权类漏洞提供有效期内的 Cookie、Authorization 等鉴权信息；这些真实值仍保留在受控原件，正文使用一致代号、必要结构和人工补填定位。不能把脱敏后的请求宣称为可直接重放。

页面重要提醒明确要求人工验证，以及危害说明、详细复现步骤、完整 PoC、关键步骤结果截图。材料不满足时交付草稿与具体缺口，不能只凭 AI 撰写或脚本推断为可提交报告，也不执行 PoC 补证。

## 正文与附件

`details` 按页面四段模板写：标题（域名/产品和类型）、漏洞描述（URL/参数/机制）、漏洞证明（步骤、完整 PoC、结果截图及实际影响）、修复方案（至少一条可执行建议）。模板还提出证明视频，缺失时明确补充事项。正文四段是同一编辑器的内容，不另建控件；保留必要标题信息，避免无意义重复。

附件文案允许 `.docx`、`.pdf`、`.zip`、`.mp4`，文件**小于 20M**；DOM `accept` 另含 Word、7z、gzip 等 MIME。优先采用文案四类格式，配置还保留 MIME 对应的 `.doc`、`.7z`、`.gz` 候选，避免把存在于控件范围但未核对的格式直接判为禁止。候选能否实际上传仍需人工核验，程序通过不等于服务端接受。20000000 字节只作保守十进制预检；字节单位和实际边界、附件总数、编辑器插图限制均未实测。

验证码与协议由用户人工处理。服务协议和 AI 处置公告全文未核对，奖励宣传不构成奖励承诺；本指南只记录页面直接显示的提醒。
