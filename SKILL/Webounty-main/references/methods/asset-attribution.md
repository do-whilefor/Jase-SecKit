# Asset attribution and discovery validity / 资产归因与发现有效性

## Use / 适用信号

用于 CT/SAN、DNS、wildcard/sinkhole、同名组织、ARN、APK/OpenAPI 路径或 CVE
watchlist 正被提升为当前资产、共享设施或适用漏洞的场景。重点是证书透明度、子域名、
解析器、伪造域名、资产归属、当前可达性与版本适用性之间的证据缺口。

本卡提供方法，不证明任何资产存在、在授权范围内、共享数据库或存在漏洞。原文案例均为
Web-Vulnhunt 的历史陈述；此处没有外部核实其中 CVE 编号、受影响版本或具体案例。

## Preconditions / 前提

先指定候选对象、观察时间、解析器/环境、查询类型、来源产物版本和正在判断的命题。
资产身份、归属/范围、可达性、部署版本、CVE 适用性是五个分别取证的命题。命名规律与
通配政策不自动决定客户归属或授权；后续主动操作依赖实际范围记录。本卡可仅分析本地证据。

DNS 解释需要命令/传输状态、DNS rcode 和应答段，不能只有 `dig +short`。已知正常
对象可作为观察器对照；高熵随机名称只是负对照候选，在通配区域不能保证不存在。
按问题核对 A/AAAA/CNAME，明确选择的解析器和网络路径。

## Test / 最小判别步骤

1. CT/SAN 记录先存为带时间的名称候选。证书历史、私有或停用名称仍可提供命名情报，
   但不变成当前可达目标。APK、SPA 和 OpenAPI 路径只提供接口候选；部署和路由另证。
2. 可疑 DNS 结果比较不同负对照名称与已知正常对象。区分 NXDOMAIN、NOERROR 无答案、
   SERVFAIL、超时、命令失败和仅 CNAME 输出。基准测试 IPv4 地址用 CIDR 判断：
   `198.18.0.0/15` 仅包含 `198.18.*.*` 与 `198.19.*.*`，不含 `198.20–31.*.*`。
   此类响应描述当前环境，不能证明全球污染、特定 sinkhole 操作者或目标必然不存在。
3. 已有 HTTP/TLS 观察只有在解析器、代理、Host/SNI、端点身份及响应来源可归因时，
   才支持当前可达性。HTTP 000 表示未记录到 HTTP 响应；门户/代理也能回 200。
   两者都不独立决定目标存活；CT 发现之后仍需可信访问路径验证。
4. 运行时指纹绑定具体组件和路由。egress User-Agent、错误模板或版本字段只是有条件
   信号；代理、可伪造头和陈旧元数据是替代解释。相同 feature payload 或 IAM 角色名
   不能单独证明共享数据库、同一代码部署或跨租户访问。
5. watchlist 保持开放假设。先取权威公告、受影响/修复版本范围，再核对实际组件、配置、
   部署和可达前提。框架家族或 CVE 字符串命中不足以成立。端点移除可能是开关或路由
   变化，不证明供应商承认漏洞、已有代码修复或历史漏洞真实。

## Confirm / 可支持的结论

逐项表述：“这份证书在该时间列出该名称”“该解析器对负对照返回此应答”“可归因的
部署返回此响应”，各自引用原始产物。CVE 适用性须有已核查公告与部署条件；复现和
影响还需独立有效实验，不继承 watchlist 的断言。多个转述不增加独立佐证。

## Refute / 反证

通配/门户对照可反驳 DNS/HTTP 单独推导的存活结论；不同归属标识可反驳同名归因；
有效的组件/版本/配置比较可排除特定 CVE 前提；受控路由差异可反驳静态到动态连接。
反证保留原观察及解析器、host、路由、组件、时间条件，不扩大为全局否定。

## Observer invalid / 观察器失效

空输出、被吞掉的错误、未知解析器、陈旧响应、缺正常对照、被过滤请求或响应身份不明，
均保留 inconclusive。原 sinkhole 脚本的 IPv4 正则过宽，且将 `dig +short` 空输出标成
NXDOMAIN/CLEAN；不能直接采用其 verdict。SHA256 证明源字节一致，不证明叙述或 CVE 范围真实。

## Stop and reopen / 停止与重开

归因或观察器未成立时停止依赖分支，保存候选并明确缺少的前提。只有解析环境改变、
取得当前可归因服务响应、权威归属/范围记录、核查过的公告/版本/配置，或新的独立证据，
才重开相应分支。不使用相同失效观察器反复枚举；保留仍有效的历史事实。
