# 检索与链路组合

## 查询与输出

按任务选择 `read/context/discover/compare`，问题级检查和停止重复检索见 [问题级检索](question-retrieval.md)。默认 `context --mode combined` 保留本节描述的词法与关系发现；显式 `--mode lexical` 跳过能力供需发现及 cursor 的变化影响展开，仍保留来源、反证、页面校验和差量交付。它没有覆盖能力组合，不能据空的 chain_discovery 推断不存在链路。

context 在当前运行的全部记录、实体、观察和 Wiki 块中检索。词法算法保留中文二元切词、接口标识、别名、精确 ID、标题权重及导航降权；统一 Unicode 字宽，并保留 camelCase / PascalCase 标识整体及其组成词。来源、显式更正和反证沿引用补齐。不需要 Embedding、向量服务或独立模型调用。

多词自然语言查询过滤常见虚词，单词查询、引号/反引号中的词、显式路径和否定词保留；原件仍完整索引。单引号、双引号、中文引号、Windows/Unix 路径及代码标识符使用同一保护规则，避免其中的 is、to、for 等被误删或扩展。保护词项不等于整句精确匹配。reopen_when 与 blockers/unresolved_preconditions/capability.needs 单独参与字段评分。

`scripts/query_expansion.py` 维护少量可审查的中英业务词组（如下载/download、报告/report）。只从原始自然语言查询扩展一次，每组新增词项总权重不超过 0.3；引号、反引号、路径、URL 和代码标识符不扩展。这不是任意跨语言翻译，不推断身份或权限等价，不修改原件、aliases 或能力供需类型。命中理由 `query_expansion` 列出实际命中的扩展词。

BM25 风格字段评分叠加原词覆盖和同句有序邻近信号。派生索引为记录、Wiki 和观察字段保留距离不超过三个词项的有序对，中文沿用相邻双字词项；不跨句号、分号或换行，重复相同词对不累计加分。大型 source_path 原件继续使用原有流式词法索引，不额外建立词对。`ordered_proximity` 表示排序线索，不代表句子语义或否定关系已被理解。

提供 `--current-conditions` 时，仅比较显式传入的条件轴，匹配给予有限加分、冲突有限降分，未知中性；冲突资料仍返回并经过原有适用性检查。块条件覆盖继承的页面条件，不从能力产物的 constraints 推断执行身份。`execution_conditions` 给出匹配、冲突和未知项；精确 ID 与显式锚点优先级不变。

自动生成的记录镜像只有在唯一来源存在、修订一致、无额外知识/条件/依赖且页面可用时才折叠到原记录，取最大匹配分数而不叠加副本，在候选上限之前去重。镜像正文按当前原记录建立词项，生成页面中的修订历史不会把旧结论重新提升为当前命中；标题或目录的独有词仍可定位原记录，理由为 `record_mirror`。页面新资料检查和原件校验仍执行。旧镜像不提升已修改的原记录，作者独立解释块不折叠，精确请求块 ID 仍返回该块。

重开查询优先包含实际变化和原先缺口，例如“下载记录的 reopen_when：取得同租户会话”；宿主可从返回的引用精读，再改写业务同义词或字段名。关键词未命中只表示本轮词法查询未定位到，不自动触发模型扩写、网络搜索或无界重试。

Wiki 的父子关系派生祖先标题路径，与块标题、summary、questions、keywords 一起参与检索。目录仅影响相关性，不限制全会话供需发现，也不能将“可回答的问题”当作已验证事实。父标题改名或移动会更新后代检索投影，稳定块 ID 保持不变。

record 在资料提交后同步本会话 `cache/retrieval.sqlite`，成功时返回 retrieval_index 统计；失败时返回已提交状态与警告，后续查询重新核对缓存，不重交已有观察。提交携带变化记录、实体、观察、页面及相关对象引用；索引利用持久化依赖反查更新受影响条目，删除旧块词项并增量维护评分所需的字段统计。目录变化更新后代投影；新反证和来源变化使相关知识检索字段重新检查。原件未变时不重复分词。

热查询读取词项倒排，不重算全部文档的依赖签名。索引保留对应 state/manifest 文件指纹与状态修订；缓存缺失、格式更新或元数据在提交入口之外被修改时，按当前资料重新核对。普通原件、页面的外部修改由文件指纹发现，相关条目重新校验；混合快照不能提交成下一次查询的有效索引。

词项、原件窗口和变化依赖的 SQLite 查询由本次查询词或变化引用驱动，按索引读取匹配行，避免临时表缺少统计信息时扫描全部倒排项。`python3 -B tests/benchmark_retrieval_efficiency.py --documents 10000 --repeats 15` 可复测合成稀疏查询的投影耗时和 SQLite VM 步数；它不包含完整 context 的文件巡检、哈希校验和装包耗时。

`cache/metadata.sqlite` 按 ID 保存记录、实体、观察、工件、页面和块的派生元数据，以及供需名称、别名、来源、反证、目录路径和变化影响的查询索引。提交只替换变化对象及其旧关系；页面删除的块同时移除，祖先改名更新后代目录投影。索引不保存原始响应正文，不新增事实。

context、discover、read、compare 在 state/manifest 文件指纹匹配时按需读取这些条目，不解析整份 JSON，也不重新分词全部能力描述或构建全会话供需表。候选组合的启动条件只计算候选边涉及的节点和相关消费者；其他记录没有参与该候选图的连接，不影响它的启动结果。检索和供需发现仍覆盖整个会话，条件冲突、反证和弱匹配建议继续保留。

命中仍回到当前页面和证据校验哈希、修订及来源。缓存是可删除重建的派生索引，不跨会话共享。读取者使用与来源文件指纹绑定的 SQLite 快照；单写者提交新状态后，旧读取者不能把过期快照当作当前证据。缓存缺失、格式变更或元数据文件在提交入口之外被修改时从 JSON 重建，即使 state_revision 没变也重新核对。

读取资料前先恢复上次未完成的发布；另一执行者正在安装时拒绝读取，已有读取仍需通过文件指纹检查。发布锁和恢复日志保护脚本入口，不把直接读取多个文件变成原子快照。发布失败恢复与缓存重建是两件事：前者恢复未提交的文件批次，后者只重新派生索引，均不提供已提交历史版本的回滚。细节见 [存储与提交](storage.md)。

发布时的 `cache/page-checks.json` 若损坏会丢弃无效条目并重新检查。权威 state/manifest 无法读取时拒绝发布，避免用空页面索引覆盖已有资料；这类错误需要修复原文件，不能按派生缓存处理。

`cache/retrieval.sqlite` 确认为 SQLite 文件损坏时，先关闭本次连接再重建；失败不无限重试。`cache/metadata.sqlite` 在打开或保存阶段发现确定损坏时同样重建；已打开快照在后续按行读取时才发现的损坏仍报告错误。元数据缓存缺少所需表或字段、头信息无效或版本过期时，也从当前 JSON 重建完整条目与关系。锁定、权限和 I/O 错误仍报告，不将它们误当文件损坏而删除数据库；Windows 上若旧读取者仍占用损坏数据库，需待其关闭后重试。发生在资料提交之后的缓存失败以警告返回，不撤销资料。

游标 JSON 损坏时重新交付当前资料，并用 `delta.reset_reason: invalid_cursor` 说明；`--refresh` 直接忽略旧游标。游标只在完整写入临时文件后原子替换，失败交付不确认已读。

一次查询内复用已解析的受限资料路径；新的查询重新检查。普通词法查询仍巡检已登记原件和页面的文件状态，精读仍验证所需原件的完整哈希；这部分成本随文件数量和原件大小增长。提交和完整审计仍读取全量 JSON 元数据，广泛命中及高扇出关系也有相应开销，不承诺恒定查询时间。

`python3 -B tests/evaluate_local_ranking.py` 报告固定虚构语料的 MRR、Recall@5、nDCG@5 和无答案案例表现，可用 `--scripts-dir` 对照另一版代码。它衡量候选相关性，不衡量答案正确性。metrics 中的 metadata_rows_loaded、relation_lookups、file_checks、signature_checks 与分词数量用于区分条目读取、文件巡检和索引更新；阶段计时可能嵌套，不应相加当总耗时。

结构化链路中的内部引用 ID 不充当正文词项；真实原始请求和响应仍可全文检索。哈希或定位失效的 Wiki 块退出普通词法候选，按精确 ID 读取时仍返回失效诊断。已知目标 ID 时可直接 read；使用 `context --query '' --anchor ID` 则跳过无用全文分词，继续补齐目标依据和能力关系。

`source_path` 导入的 UTF-8 文本原件也参与词法检索，命中归属其观察 ID。索引按带重叠的原文字节窗口提取词项并保存定位，不将这些窗口登记为独立观察。窗口边界保留完整标识符，重叠起点不制造截断词；中文保留连续双字词项。64 KiB 是窗口目标，遇到超长标识符时等待词边界，内存随窗口及最长标识符增长。source_match 给出一个词项相关窗口及 matching_chunks 数量；选窗先比较原始查询词的命中数，再比较包含扩展词的总命中数，matched_original_query_terms 显示原词覆盖。evidence 固定为 false；它不是语义摘要，也不表示其他窗口无关。

原件 ID、路径及 SHA-256 必须与封存观察中的 source_artifact 声明一致，错配返回 observation_source_mismatch，观察不可用且不再索引该来源。source_match 只属于当前查询，切换查询或仅按 ID 定位时不会沿用旧窗口。按其 artifact_id、offset、length 精读后，可将返回的 range.sha256 与窗口 sha256 核对。

仅手工在 state 中挂接 source_artifact_id、封存观察中没有对应声明的旧资料也会触发该诊断。应核对原件后通过 source_path 导入为新的观察 ID，保留旧资料供复核，不直接改写封存观察补字段。

使用 `read --id SRC-ID --offset N --length N` 读取原件。返回实际字节范围、哈希、next_offset 与 eof；UTF-8 被范围边界切开或原件为二进制时，用明确标注的 base64 保留字节。未给范围时 read 保持完整读取。二进制资料只保存与验证，不自动解析 PDF、图片、压缩包或执行 OCR。

单文件 16 MiB、累计读取 64 MiB 和 12,000 项的原型拒绝上限已经移除。大型 source_path 原件流式复制、哈希与分段建索引；小字节缓存有内存预算，超出预算只停止缓存，不拒绝资料。大 JSON observation 仍按单个 JSON 对象解析；state/manifest 在提交、完整审计或缓存重建时整体读取。大正文优先保存在 source_path，不放进庞大的 content 字符串。命中来源的完整哈希检查仍读取所需原件，完整 evidence/read 视图按请求展开正文。

`python3 -m unittest discover -s tests -p 'test_source_chunk_boundaries.py'` 检查跨窗口标识符、Unicode 归一化、原文字节定位、连续中文窗口，以及冷/热/重建索引的一致性。这些边界回归不代表任意文件规模的性能保证。

精确命中或最高词法命中的记录若已有显式反证/替代记录，将该关联提前展示；其余命中的显式反证在所属结果之后补齐，不因低相关记录的反证挤掉主要命中。原因标为 counterevidence_relation；所有精确请求仍优先。这表示需要一起阅读的竞争结论，不把新记录自动当真，也不隐藏旧观察。

能力供需发现发生在最终装包前，扫描整个会话，不要求消费者先命中文字查询。chain_discovery 的 candidates、paths、combinations 和 type_reviews 固定 evidence:false，是后续阅读入口。

供需发现同时检查 observation_refs 和显式 artifact_refs，包括原件哈希及声明的行位置；缺失、损坏或定位失效会使对应来源不可用，并沿上游来源传递。候选的 artifact_refs 给出可读取的原件 ID，只有原件引用的记录也可提供来源入口；检查通过仍不表示原件支持作者结论。

供需类型与别名的双向索引在提交时维护，从锚点逐步展开相关分支；来源与更正的反向索引也按变化对象更新。冲突连接作为诊断保留，无锚点时仍搜索全会话。默认不设置预算时，结果按 ID 去重累积后统一排序、计算大小，避免每增加一项都重排和测量完整输出。完整性检查仍回到当前原件，缓存只在本会话复用。

默认不设置字符或候选硬上限。需要分批阅读时显式指定 --budget-chars 或 --max-candidates，检查遗漏提示再按 ID 补取；这些参数不修改模型的输入、输出或思考 Token 额度。完整语义单元不截成半句，遗漏不能支持不存在或已覆盖的结论。

旧的观察对照配对通过 --cross-limit N 按需启用，寻找同对象/接口/流程的对照；它与能力供需发现是不同功能。

## 紧凑视图与跨轮变化

`session.py context` 和 `rag.py` 命令默认 `--view compact`；Python `retrieve()` 的底层默认仍是 evidence。compact 保留当前判断、适用条件、供需、反证、缺口和证据定位；原始观察、来源文件及修订历史按 ID 精读。自动生成的记录说明块引用同包记录，不重复渲染；人工语义块保留完整解释，summary 不替代正文中的限制条件。

compact 在装包时直接构建所需字段，不先展开整份原始响应和来源正文再删除。哈希、来源闭包与知识有效性仍用当前原件验证；词法索引和观察对照仍按需读取原始观察。减少的是重复文本展开与序列化，不是免除证据检查。

检索范围始终是全会话。compact 仅将与当前命中、来源或关系关联的未分类资料装包；另有未关联资料时给出计数，不把它们冒充当前问题的证据。完整 evidence 视图保留全量未分类材料的原读取方式。未命中不表示不存在。

- `context ... --cursor main`：首次返回当前完整视图；以后按稳定 ID、内容与依赖签名只返回新增或变化项，unchanged_refs 指向本次相关且该游标曾返回的内容。
- `context ... --cursor main --refresh`：清除该游标的已返回记忆，重新发送当前查询视图。上下文压缩或更换读取者后使用；仅恢复当前查询，其他问题稍后正常重新检索。
- `context ... --cursor main --context-epoch E2`：宿主为同一读取者维护代次；与上次不同就重置该游标，并在 delta.reset_reason 标为 context_epoch_changed。开始使用后保持传入，同代次正常去重。没有宿主代次支持时用 --refresh，脚本不感知模型是否遗忘。
- `context ... --view evidence`：返回完整材料；`read ... --id ID` 可精读记录、块、观察或来源工件。读取原件前不把引用当作已读原文。

游标只记录交付签名，不记录第二份事实，也不表示宿主已理解或永久记住内容。新查询没有命中某个 ID 不等于该资料已删除；新反证、来源失效和适用条件变化仍需显式处理。标题或目录变化与判断内容变化分开标记。不同读取者使用不同 cursor。

task_core 在 compact 或带 cursor 的视图中每次重发：当前 Goal 的目标与硬约束、当前问题、已声明 next_action、显式 current_conditions 和需要复核的记录引用。它是现有状态的投影，不复制另一套事实。旧版游标首次读取会重新发送资料；现有 state、Wiki 和原件可继续读取，派生词项索引按版本重建。

`delta.removed_refs` 仅在完整当前 manifest 确认先前交付的 Wiki 块已被移除时发出；读取者应撤下该块的旧视图。它可以与当前问题的命中无关，依据是本会话成员变化。换查询、页面不可读取或 manifest 缺失都不据此推断删除。它不删除原件，也不说明相关漏洞已经修复。

组合和表达复核也参与差量交付。`delta.combination_changes` 比较该游标上次收到的覆盖及分支依赖，列出变化的 need_index；来源修订即使没有改变覆盖，也会要求重看对应输入。`delta.retired_refs` 仅撤下本次实际重查消费者后消失的旧组合/表达提示，读取者应从保留视图中移除它们；不表示漏洞已解决。不同查询未命中、资料不可用或预算遗漏不会据此撤下旧提示。派生 ID 用于交付定位，精读应使用其中的 record_refs。

默认无字符上限。带 cursor 时先验证当前资料并计算实际差量，再按显式预算检查，已交付且未变化的长正文不重复收费。差量仍超预算时尝试按完整单元选择较小材料包；遗漏明确报告。task_core、问题检查和差量提示也计入预算，放不下则 budget_exhausted 且不推进游标；不截断结论中的条件或反证。恢复代次后必须重新容纳正文，不能继续依赖旧上下文。该预算只控制脚本交付字符数，不修改模型额度。

read/context/discover 使用相同的依据检查：来源 revision 不一致为 stale_source，已标记的依赖为 basis_review_required，更正关系单独保留。可传 --current-conditions 检查记录顶层 conditions 对当前执行条件是否适用；不传则没有这项检查。检查结论不等于现场复测。

## 变化影响

record 返回 change_impact，列出变化来源涉及的记录、页面、既有 Chain、候选路径和需重看的供需连接。原因与 via_refs 指出传播依据；新能力即使没有被旧失败记录显式引用，也可通过全会话候选关系提示重看该阻塞点。条件冲突和未知前提保持可见。

`affected_combinations` 复用本次发现的组合，按输入列出受影响的直接备选、选中分支的上游来源及当前缺口，不再次运行发现，也不重复返回完整方案。只有相关分支受影响时，不把其他独立输入一并标为变化。

changed 请求还沿无显式条件冲突的下游引用寻找待复核组合，避免上游撤销后失去下游提示；这只扩大复核范围，不恢复失效来源的可用性。普通 anchor/query 的展开规则不变。

已有 cursor 的 context 在返回新增或变化资料时附带影响提示，basis 为 new_or_changed_since_cursor_delivery；它同时包含世界状态的变化和读取者首次收到的资料，不能当作全局事件日志。首次查询、refresh 和完全未变的重复查询不重复附加该提示。所有影响项均 evidence:false，不能据此把候选或旧失败自动升级为已验证；按引用复读原件后更新判断。

## 可组合的能力

在记录的 capability 中填写：

```json
{
  "provides": [{
    "type": "report-job-id",
    "aliases": ["导出任务标识"],
    "description": "本次响应返回的任务标识",
    "constraints": {"environment": "lab-v1", "tenant": "tenant-a", "purpose": "report-export"}
  }],
  "needs": [{
    "type": "member-session",
    "description": "有效成员身份",
    "constraints": {"environment": "lab-v1", "tenant": "tenant-a"}
  }],
  "control": "可选择本账号拥有的报表"
}
```

同一类型使用一致名称，别名只填真正同义名称，不用泛化别名把所有凭据合并。needs 是同时需要的前提；替代方案分别建记录。不要用空字符串表示任意条件，不为提高匹配率补造环境或身份。

常用条件维度：actor、tenant、resource、environment、purpose、audience、credential_generation、target_version。必要时可增加其他字符串维度。

## 使用候选

record 后先读返回的新关系，不立即重复相同查询。新增能力/消费者时用 changed；目标受阻时用 anchor 指向带 needs 的 Goal/Step。候选定位后 read 双方记录和页面，核实来源、限制与反证。

- compatible：声明条件可机械对应；仍非端到端验证。
- incompatible：已知条件冲突，保留具体冲突帮助判断。
- unknown：条件、来源、状态或前提不全，需要查证。

条件值 unknown、unspecified、not_recorded、未知、未记录、空白，以及缺少字段都按未知处理；两个相同的未知占位符不能满足前提。“不适用”应由作者按实际语义明确表达，不能拿 unknown 当通配符。

producer_usable / consumer_usable 只表示该记录未被状态、反证或来源检查排除出候选展开；true 不是业务成功或漏洞成立。candidate 状态仍会产生 record_tentative，连接可同时为 unknown。

路径是在锚点/变化点相关分支中选择的代表性候选，不穷举全部组合，不保证找到所有链。循环前提不能自行启动，需要实际可用的起始能力。

路径 missing_preconditions 中的 no_prior_provider_in_path 只表示这条路径没有前置提供者，不表示全会话没有该能力。多输入消费者另有稳定 ID 的 `combinations`，自动汇合独立分支：

- inputs：所有 needs 同时需要；每个输入的 alternatives 是提供者引用。candidate_ready 表示存在声明兼容、来源可用且递归前提可启动的分支。
- plan：一个代表方案的 bindings、递归缺口及共同条件诊断。coverage.required/covered 包含选中分支的上游输入；complete 还要求共同条件没有冲突或未知。
- 同名条件在选中记录之间不同、或某分支未声明时，分别列入 conflicts / unknown_conditions。这是保守的复核提示；不同阶段或角色的差异是否合理，须阅读原记录判断。

例如 A 提供任务标识、B 提供下载授权、C 同时需要两者，bindings 为 A→C 和 B→C。不生成 A→B 的虚构依赖。多个备选保留引用，不做笛卡尔积穷举；当前代表方案未闭合不排除其他备选组合可行。循环前提没有外部起点时保持缺口。

`type_reviews` 检查当前发现范围内没有完整类型/别名匹配的 needs，只用该输入的类型、别名和描述，在全会话提供者的类型、别名、描述和摘要中查词面重合；消费者整条摘要不参与，以免其他输入干扰当前缺口。它使用 Unicode 规范化、英文词项和中文二元词项；没有跨语言翻译或语义向量能力。

如果已有完整匹配，但本次 candidates 已确认这些提供者全部失效或显式条件冲突，则以 `all_complete_matches_unusable_review_alternatives` 提示复核不同表达的替代能力。原有冲突和反证继续保留，不误报为类型缺失。任何匹配仍可用、仅为 unknown、消费者失效或诊断不完整时，不据此启动替代提示。没有词面建议也不表示不存在替代能力。

suggestions 保留 matched_terms、双方条件、冲突和来源引用；相关原件按需 read，不为弱提示自动展开进证据包。确认同义后显式修订 type/aliases，下一次检索使用新映射。组合、表达提示均是当前记录的派生视图，不写回事实；值得持续研究的方案由 Claude 保存成 Chain。

`python3 -B tests/benchmark_discovery.py --sizes 1000 3000` 可复现同类型、不同租户分组的局部发现基准，报告耗时、结果哈希和条件检查次数。它测量内存中的关系发现，不代表网络请求、文件读取或 Claude 推理耗时。

## 保存与验证链路

Chain.links 记录 producer、consumer、provide/need 下标、assessment、连接观察和条件。多个产物中明确哪一个实际进入下游。

相同类型、两端分别可用、状态码相同，都不能升级为 verified。必须有产物实际被消费的证据，并核对所有前提。整链 verified 还需要最终结果及各步骤条件同时成立。脚本检查引用和必需项，业务真实性仍由 Claude 回到证据判断。

新反证或来源变更会要求复核受影响解释。旧失败的前提若已被新能力补齐，形成新实验；不能直接宣布成功。
