# 单会话 Wiki 的组织与写法

同一会话的目标、问题、发现和候选链共享一份 Wiki。下一轮继续更新同一记录与规范页；新观察另用一个不可变的观察 ID。一次回复、一项负结果或一个发现完成，都不意味着清空本会话。

## 总览与规范页

`wiki/index.md` 根据当前状态生成，按以下入口组织：

| 入口 | 内容 |
|---|---|
| 当前目标 | 当前任务及其状态；未建立页面的目标定位到状态文件 |
| 活动问题 | 未解决的 Question，以及正在判断、受阻或未完成的 Step；工具失败不会自动归为反证 |
| 发现 | 已有线索、观察及作者声明已验证的发现，明确区分状态 |
| 负结果与关闭命题 | 明确被反证或仅在指定条件下关闭的命题 |
| 能力 | 可提供的输出、所需前提及其适用约束 |
| 链与阻断 | 组成能力、连接声明、未满足前提和当前阻断 |

事实及已完成步骤另列为资料；业务页和辅助解释页可以保留。首页只导航和提示变化，不成为新的原始证据。

一条记录选择一个规范页：优先已有自动主页，其次为专门描述该记录的页面，再次为包含它的业务页。引用可以出现在多处，正文解释维护在一个主要位置。修改已有解释时沿用页面 ID，不按第几轮另建同内容副本。

自动页通常使用 `WK-<record-id>`。提交 `pages` 可以编辑正文；这种作者页面在来源改变后保留原文并显示待复核，只有再次提交该页面时才重写。首页和检索返回的页面检查是判断是否过期的依据，不能只打开一个旧 Markdown 就沿用其判断。

## 结构导航与检索判断块

按实际问题建立可选的页面父子关系，例如“报表服务 → 导出流程 → 下载授权”。页面使用 `parent_page_id`，块属于其所在页面。检索路径由父页面的当前标题生成；标题、页面位置和文件锚点不是同一身份，改名或移动仍沿用原页面与块 ID。

目录帮助区分不同流程里同名的“验证结果”，但检索仍覆盖全会话关键词、明确 ID 和能力供需。其他目录中的能力、前提和反证不因不在当前分支而被排除。父子关系是组织信息，不是支持、反驳或能力连接关系。

正文以完整判断为单位：当前结论、适用条件、支持证据引用、反证或未验证部分、下一缺口。不要按字符数切开结论与其限制。需要补读另一块的必要条件时显式使用 `required_block_refs`；长请求响应留在 `evidence/` 按引用读取。

页面或块的可选 `summary / questions / keywords / aliases` 描述它涉及什么问题，以帮助表达不同的查询找到同一知识。`questions` 优先保留实际多轮提问；知识发生变化时再更新相关描述，不为每轮对话重做全量问答。检索提示只是定位线索，不能把其中的假设当成新的已验证事实。

仅改标题或父位置时，提交 `id` 与改变的元数据即可，不必重传所有正文。此操作保留旧来源修订和待复核信息；真正修订判断时再提交完整块及其来源。具体格式见 [存储与提交](storage.md)。

## 单条发现或问题存什么

已有 `summary / status / conditions / observation_refs` 仍是基础。下面均为可选作者数据，不要求一次填写，也不要求为普通观察制造实验。

| 字段 | 页面如何表达 |
|---|---|
| `question / hypothesis` | 当前问题与待判命题 |
| `expected / falsifier` | 预期的支持、反证信号；与实际结果分开 |
| `actual_result`，或已有 `result / results` | 实际结果的简短描述，保留否定及未观察范围 |
| `observer / assessment` | 观察器有效性及本步判断；无效观察不能写成有效反证 |
| `controls` | 正常、负对照或比较记录，保留各自的有效性和条件 |
| `counterevidence` | 反证、竞争解释的简短描述 |
| `contradicted_by / contradicting_fact_ids / corrected_by / correction_refs` | 已有正式反证、更正关系；引用当前记录 ID |
| `unresolved_preconditions / blockers` | 尚未满足的前提、断点和所缺观察 |
| `limitations / reopen_when` | 当前结论边界及哪些变化值得重开 |
| `impact` | 影响及其验证状态；可能影响不自动升级为确认影响 |
| `retest`，或已有 `retest_result` | 复测结果、正常对照、条件变化和剩余未知 |

这些字段可用简短字符串、列表或自然的对象表达。渲染保留嵌套字段，包括 `false`、`unknown`、无效对照和否定，不把它们省略成肯定摘要。例如：

```json
{
  "hypothesis": "该入口可能返回其他对象的内容",
  "actual_result": "本次请求被拒绝，尚未观察到对象内容",
  "controls": [{"note": "合法基线也失败", "validity": "invalid"}],
  "impact": {
    "status": "unknown",
    "possible": "跨对象读取",
    "confirmed": false,
    "limitation": "当前结果不能证明读取已发生"
  },
  "reopen_when": ["有效身份和合法基线就绪后重新判断"]
}
```

`impact` 没有明确的 `status: verified` 时，自动页会标为未验证；写入这一声明也不会让脚本证明其真实性或改变记录状态。复测文字不会自动把 Finding 或 Chain 改为 `verified`。

展示字段不代替正式来源关系。所用原始观察仍登记在 `observation_refs`，支持与反证使用现有记录引用；不要只把证据 ID 埋在任意说明字段中。原始请求、响应及文件保存在 `evidence/`，页面只保存摘要与链接，不自动复制原件内容。

## 负结果、候选链与更正

一项负结果描述“哪个命题、在什么条件下、通过什么有效观察被否定”。一次 403、404、工具失败或空输出本身不是整个漏洞类别安全的证明。缺必要前提时记录受阻或未知；条件未变时不重复无增益的尝试，出现具体重开条件再重新判断。

链页链接到组成记录，显示每条连接的输出、必要输入、条件、证据和作者判断。候选连接明确标为未验证；已成立的局部能力与尚未成立的整链分别保留。无法跨越的消费者、身份、资源或环境条件是链的边界，不应从文档中删掉。

新反证、更正、来源修订或条件变化到来时，首页会显示相关旧页面的待复核原因与新记录链接。旧正文保留其历史意义；新增相关资料不自动反驳旧观察，也不自动替作者确认原结论。沿依赖受到影响、且未在同批显式复核的 Capability、Finding、Chain 使用 `needs_review` 状态；原件与历史 Fact 保留。

资料提交后还会更新受影响的词法索引；同步失败单独警告，后续查询按当前资料重新核对，不撤销已经提交的 Wiki。页面删去的块退出普通检索；来源变化保留旧解释的待复核状态，不能通过改标题或索引刷新把它变成已复核。大原文命中给出的字节窗口只用于精读，Wiki 正文仍按完整判断保存条件、反证与证据引用。

首页发布只重新读取依赖或文件发生变化的页面和原件；未变化的检查从可重建缓存复用。显式依赖的解释块待复核时，引用页同步提示。页面改名、移动目录不会刷新旧来源或抹去反证提示，也不要求重新读取无关证据。缓存只是一份检查投影，实际读取和完整审计仍校验当前资料；缓存缺失时从当前内容重建。

来源记录的 `artifact_refs` 同样参与页面校验和缓存失效，包括传递来源及行号定位；只引用文件而未声明 observation_refs 也不能跳过原件检查。`wiki knowledge` 返回判断与来源定位，验证原件哈希但不展开文件正文，合法二进制附件无需转换为文本；精读原文使用 `read`。

既有记录更新时，`history` 追加修订号、旧状态、旧摘要、更正缘由及新引用。自动历史使用 `record_refs / observation_refs`，不使用会被旧检索器当作当前依赖的 `evidence_refs`。历史区仅供回顾，现行结论仍取当前记录；不保存整份旧状态，也不提供历史版本回滚。发布恢复日志只用于恢复未完成批次，见 [存储与提交](storage.md)。操作日志仍在 `logs/`。

## 借鉴范围

本组织方式借鉴 Jase Web-Vulnhunt 的“总览—单发现详情—负结果—链阻断”分层，以及假设、检查、结果、重开条件的记录方式。未复制历史目标案例、评分结论、全部拒绝即类别安全的推断，也未引入固定报告长度、评分必填或强制提交顺序。
